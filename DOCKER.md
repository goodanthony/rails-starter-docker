# Docker development commands

These commands remain available after `rails new` replaces the starter README.
Run them from the application root.

## Application lifecycle

```bash
# Start the complete stack.
docker compose up

# Start in the background.
docker compose up -d

# Stop and remove containers, keeping data volumes.
docker compose down

# Rebuild after changing Dockerfile.starter.
docker compose build

# Follow Rails logs.
docker compose logs -f app
```

Open <http://localhost:3000> while the stack is running.

## Rails and database

```bash
# Rails console
docker compose run --rm app bin/rails console

# Show routes
docker compose run --rm app bin/rails routes

# Prepare the development and test databases
docker compose run --rm app bin/rails db:prepare

# Run pending migrations
docker compose run --rm app bin/rails db:migrate

# Roll back the latest migration
docker compose run --rm app bin/rails db:rollback

# Seed the database
docker compose run --rm app bin/rails db:seed
```

## Generators

```bash
docker compose run --rm app \
  bin/rails generate scaffold Post title:string body:text published:boolean

docker compose run --rm app \
  bin/rails generate model User email:string name:string

docker compose run --rm app \
  bin/rails generate controller Pages home about

docker compose run --rm app \
  bin/rails generate migration AddSlugToPosts slug:string:index
```

## Tests and checks

```bash
# Rails test suite
docker compose run --rm app bin/rails test

# Autoloading check
docker compose run --rm app bin/rails zeitwerk:check

# Dependency audit generated by the default Rails app
docker compose run --rm app bin/brakeman --no-pager
docker compose run --rm app bin/bundler-audit
```

## Dependencies

```bash
# Install Gemfile changes
docker compose run --rm app bundle install

# Update one gem
docker compose run --rm app bundle update GEM_NAME

# Install JavaScript dependencies for a bundler-based app
docker compose run --rm app yarn install
```

## Reset local data

`docker compose down -v` deletes both the PostgreSQL and Bundler volumes. Use it
only when you intentionally want a completely clean local environment.
